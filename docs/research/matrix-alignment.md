## 二、证据驱动的结论

1. **「桌面 = agent 指挥中心」是四家共同 thesis**——不是聊天窗口。工作台三件套成标配：**diff 审查、行内审批、任务/审查队列**
2. **diff 审查是 dev-agent 工作台的核心竞争力**（Codex/Claude Code 都把它当招牌）——必须进 v2.0 主线，不能排在 v2.1
3. **内置浏览器面板 4/4 全有、终端 3/4**——两者都是「壳层可自建、不依赖引擎暴露」的能力（node-pty 我们已捆绑）——是**低成本高对齐度**的差异化机会
4. 自动化四家全有但 DSH 无暴露面（已知）——维持插件路径判定，不阻塞 v2.0
5. 语音三家半有——维持第二梯队判定
6. Claude 的 .mcpb 本地 MCP 生态是其护城河——DSH 引擎有 mpc 包，值得后续探察，作为 Efferent 的开源对标点

## 三、SPEC-0002 工作台面的对齐修订（证据版）

**v2.0（不变部分）**：会话主视图（流式+工具卡片+行内审批/提问卡）、Composer、任务侧栏
**v2.0（升级）**：会话主视图**内嵌 diff 渲染**——从工具调用事件客户端推导（探察点：编辑类工具事件的参数形状）
**v2.1（重排）**：①**内置终端**（壳层 node-pty+xterm.js，绑定工作区）②**预览浏览器窗格**（壳层 BrowserView）③计划/目标面板（goal API）④历史搜索
**v2.2+（维持）**：自动化面板（插件分发）、语音（已有 M1/M2 验证）、MCP 生态（先探察引擎 mcp 包）
